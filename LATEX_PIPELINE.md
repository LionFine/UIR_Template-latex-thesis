# Процесс создания пояснительной записки в LaTeX

Документ описывает воспроизводимый путь от кафедрального шаблона до готовой
пояснительной записки. Текущая рабочая реализация находится в `thesis/`,
а исходный шаблон для сравнения и повторного использования сохранен в
`thesis-template/`.

## 1. Исходный шаблон

Шаблон кафедры № 22 НИЯУ МИФИ:

```text
https://gitlab.com/skibcsit/thesis-template
```

Зафиксированная в репозитории версия:

```text
fdb501224fb2e7a7e4fc1c814182de732ed1688a
```

Шаблон рассчитан на XeLaTeX, использует системные шрифты и оформляет
библиографию через BibLaTeX/Biber. Каталог `thesis-template/` нужен как
эталон: рабочие изменения выполняются в `thesis/`.

## 2. Структура рабочей ПЗ

```text
thesis/
  main.tex                         # точка входа
  latexmkrc                        # XeLaTeX, Biber, каталог build
  chapters/
    thesis-template-macro.tex      # преамбула и оформление
    0-0-project-members.tex        # автор, группа, руководитель
    0-1-task-data.tex              # тема и задание
    _content.tex                   # порядок разделов
    00-abstract.tex
    00-abbreviations.tex
    01-introduction.tex
    02-analytics.tex
    03-theory.tex
    04-architecture.tex
    05-implementation.tex
    08-conclusion.tex
    thesis-template-bibl.tex       # вывод списка литературы
    biblio.bib                     # библиографическая база
  title/                           # титульный лист и задание
  appendices/                      # приложения
  img/generated/                   # используемые схемы
  figures/ tables/ listings/       # дополнительные материалы
```

`main.tex` подключает преамбулу, титульный лист, задание и
`chapters/_content.tex`. Файл `_content.tex` является оглавлением на уровне
исходного кода: именно в нем задается последовательность глав, библиографии и
приложений.

## 3. Настройка данных работы

Сначала заполняются два файла:

1. `chapters/0-0-project-members.tex`:
   группа, студент, руководитель, консультант и тип работы.
2. `chapters/0-1-task-data.tex`:
   тема, дата выдачи задания, этапы работы, сроки и литература.

После этого редактируются отдельные файлы глав. Новую главу нужно не только
создать, но и подключить через `chapters/_content.tex`.

Библиографическая запись добавляется в `chapters/biblio.bib`, а в тексте
используется команда `\cite{ключ}`. Biber запускается автоматически через
`latexmk`.

## 4. Рисунки, таблицы и приложения

Используемые схемы RAG сохранены в `thesis/img/generated/`, потому что в этом
репозитории нет исходного генератора этих изображений. Рисунок подключается
обычной командой:

```tex
\includegraphics[width=\textwidth]{img/generated/example.png}
```

Приложения находятся в `thesis/appendices/` и подключаются в конце
`chapters/_content.tex`. Крупные листинги, таблицы и служебные материалы
рекомендуется выносить в отдельные файлы, а не размещать целиком в главе.

## 5. Сборка

Минимальные зависимости:

- MiKTeX или TeX Live;
- XeLaTeX;
- `latexmk`;
- Biber;
- Perl для `latexmk` на Windows;
- Times New Roman, Microsoft Sans Serif и Courier New.

Проверка Windows-окружения:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\check_latex_env.ps1
```

Сборка из корня репозитория:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build_thesis.ps1
```

Или напрямую:

```powershell
cd .\thesis
latexmk -xelatex main.tex
```

`thesis/latexmkrc` направляет все временные файлы и итоговый PDF в
`thesis/build/`. Ручной эквивалент сборки:

```text
xelatex main.tex
biber main
xelatex main.tex
xelatex main.tex
```

## 6. Альтернативные титульные листы

В `main.tex` оставлены примеры `\includepdf`. Они позволяют заменить
LaTeX-титульник или задание официальным PDF кафедры. Исходные PDF-бланки из
шаблона сохранены, но по умолчанию используются редактируемые `.tex`-версии.

## 7. Что хранится в Git

Хранятся:

- весь исходный кафедральный шаблон;
- все `.tex`, `.bib`, `.cls`, `.sty` и настройки сборки;
- PDF-бланки и демонстрационные изображения шаблона;
- изображения, используемые рабочей ПЗ;
- скрипты и документация.

Не хранятся:

- `thesis/build/` и `thesis/out/`;
- логи, индексы, SyncTeX и другие воспроизводимые результаты компиляции;
- токены, пароли и локальные настройки редактора.

## 8. Проверка готового документа

После сборки следует проверить:

1. данные титульного листа и задания;
2. оглавление и нумерацию страниц;
3. ссылки на рисунки, таблицы и литературу;
4. отсутствие предупреждений об отсутствующих файлах и ссылках;
5. список литературы по ГОСТ;
6. порядок и нумерацию приложений;
7. отсутствие личных или служебных данных, которые нельзя публиковать.
